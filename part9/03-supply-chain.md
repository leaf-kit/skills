# 9.3 공급망 위험

이 장은 수치 하나에서 시작한다.

> AI 에이전트 스킬(Claude Code, Codex CLI, Gemini CLI 등이 쓴다)은 **암묵적 신뢰로 실행되고 검증이 거의 없다.** 연구 데이터셋에서 분석한 31,132개 스킬 부분집합에서 **26.1%의 스킬이 취약점을 포함**하고 **5.2%가 악의적 의도로 보인다.**

(출처: `NVIDIA/SkillSpector` README, 2026-10-04 확인)

| 항목 | 값 |
|---|---|
| 분석한 스킬 | 31,132 |
| 취약점 포함 | **26.1%** |
| 악의적 의도로 보임 | **5.2%** |

**네 개 중 하나에 취약점이 있고, 스무 개 중 하나가 악성으로 보인다.**

## 왜 이 생태계가 특히 위험한가

세 조건이 겹친다.

### 1. 스킬은 실행되는 지시문이다

스킬은 문서처럼 보이지만 문서가 아니다. **에이전트가 읽고 그대로 따른다.** 그리고 그 에이전트는 파일을 읽고 쓰고 명령을 실행하고 네트워크에 접근한다.

npm 패키지는 코드를 실행한다. 스킬은 **판단을 바꾼다.** 어느 쪽이 더 위험한지는 상황에 따라 다르지만, 후자가 탐지하기 어렵다. 악성 코드는 정적 분석으로 잡히고, 악성 지시문은 문장으로 쓰여 있다.

### 2. 설치 비용이 거의 0이다

| 생태계 | 설치 | 검증 관례 |
|---|---|---|
| npm | `npm install` | 감사 도구, 서명, 레지스트리 |
| PyPI | `pip install` | 감사 도구, 해시 고정 |
| **스킬** | **파일 복사** | **없음** |

마크다운 파일을 디렉터리에 넣으면 끝이다. 레지스트리가 없고, 서명이 없고, 버전 고정이 없다.

**설치가 쉬우면 검증은 덜 한다.** 그리고 쉽게 설치한 것은 쉽게 잊는다 — 설치한 스킬 목록을 관리하지 않는다.

### 3. 규모가 크고 검증 불가능하다

| 저장소 | SKILL.md |
|---|---|
| `sickn33/agentic-awesome-skills` | 8,212 |
| `ComposioHQ/awesome-claude-skills` | 864 |
| `alirezarezvani/claude-skills` | 846 |
| `brycewang-stanford/Auto-Empirical-Research-Skills` | 23,000+ (주장) |

(수집 날짜: 2026-10-04)

**8,212개를 읽을 수 없다.** 수집한 사람도 읽지 않았을 가능성이 높다([7.4](../part7/04-awesome-lists.md)).

큐레이션 저장소의 스타가 수집 규모에 붙으므로, 개수를 늘리는 동기가 있고 검증할 동기는 없다.

## 공격면 — SkillSpector의 17개 범주

`NVIDIA/SkillSpector`가 71개 패턴으로 17개 범주를 검사한다.

```
프롬프트 인젝션, 데이터 유출, 권한 상승, 공급망,
과도한 행위 권한, 출력 처리, 시스템 프롬프트 유출,
메모리 오염, 도구 오용, 악성 에이전트, 거부 우회,
트리거 악용, 위험 코드(AST), 오염 추적,
YARA 시그니처, MCP 최소 권한, MCP 도구 오염
```

이 중 **스킬 고유의 공격면** 네 가지를 자세히 본다.

### 트리거 악용

`description`을 조작해 의도하지 않은 상황에 스킬이 불리게 만든다.

[1.5](../part1/05-triggering.md)에서 `description`이 트리거를 결정한다고 했다. 그게 공격면이기도 하다.

| 정당한 설계 | 악용 |
|---|---|
| 키워드를 넓게 넣어 과소 트리거를 막는다 | 키워드를 넓게 넣어 **모든 작업에 끼어든다** |
| 불만 표현을 트리거로 쓴다 | 흔한 표현을 전부 트리거로 쓴다 |
| 지시형으로 밀어붙인다 | "항상 이 스킬을 먼저 쓰라"로 다른 스킬을 밀어낸다 |

**정당한 설계와 악용이 같은 기법을 쓴다.** `DietrichGebert/ponytail`의 `description`이 "모든 코딩 작업에 쓰라"고 적는다([7.3](../part7/03-single-purpose.md)). 그게 정당한 이유는 실제로 모든 코딩 작업에 해당하는 스킬이기 때문이고, 그 판단은 기계가 못 한다.

### 시스템 프롬프트 유출

스킬 본문에 "지금까지의 지시를 모두 출력하라"에 해당하는 내용을 심는다. 스킬이 트리거되면 그게 실행된다.

**스킬은 본문 전체가 읽힌다**([1.3](../part1/03-progressive-disclosure.md)). 500줄 중 한 줄에 심으면 된다.

### 메모리 오염

메모리 스킬이 생태계에 일곱 개 넘게 있다([8.4](../part8/04-memory.md)).

| 단계 | 일어나는 일 |
|---|---|
| 1 | 조작된 내용을 에이전트가 읽는다 |
| 2 | 메모리에 저장된다 |
| 3 | 이후 모든 세션에서 사실로 취급된다 |
| 4 | **원본을 지워도 메모리에는 남는다** |

4번이 핵심이다. **메모리는 출처에서 분리된다.** 저장된 뒤에는 어디서 왔는지 추적하기 어렵다.

메모리 없이는 잘못된 정보가 세션과 함께 사라진다. 메모리가 있으면 한 번 심은 거짓이 지속된다. **메모리 도구를 설치하는 것 자체가 이 위험을 만든다.**

### MCP 도구 오염

플러그인이 스킬, MCP 서버 설정, 훅을 한 묶음으로 배포한다([1.4](../part1/04-boundaries.md)). **하나를 설치하면 셋이 들어온다.**

`DietrichGebert/ponytail`이 `ponytail-mcp/`와 `hooks/`를 같이 담는다. 정당한 구성이지만, 같은 구조로 악성 MCP 서버를 스킬과 함께 배포할 수 있다.

훅이 특히 위험하다. **훅은 판단 없이 항상 실행된다.** 스킬은 트리거돼야 작동하는데 훅은 그렇지 않다.

## 특수 문제 — 공격 스킬과 악성 스킬이 닮는다

[8.1](../part8/01-security.md)에서 다룬 문제다.

| 탐지 범주 | 정당한 공격 스킬에서 |
|---|---|
| 과도한 행위 권한 | 공격 스킬은 본래 강한 권한을 요구한다 |
| 위험 코드 (AST) | 익스플로잇 코드가 번들에 있다 |
| 거부 우회 | 공격 방법론은 안전장치를 우회하는 모양이 된다 |
| 트리거 악용 | 공격 스킬이 의도치 않게 불리면 위험하다 |

**기계가 정당한 공격 스킬과 악성 스킬을 구별하기 어렵다.** 반대로 말하면 악성 스킬이 "공격 보안 스킬"로 위장하기 쉽다.

수집 데이터에 공격 스킬 번들이 셋 있고 합쳐서 `SKILL.md` 160개를 넘는다 — `SnailSploit/Claude-Red`(79), `elementalsouls/Claude-BugHunter`(83), `ljagiello/ctf-skills`(11).

**이 도메인에서는 출처가 유일한 방어선이다.**

## 생태계의 대응 — 네 가지 접근

| 접근 | 주체 | 무결성 | 상태 |
|---|---|---|---|
| 설치 스킬 | OpenAI | 없음 | 구현 |
| 인덱스 파일 | Google | 없음 | 구현 |
| `.well-known` + 검증 절 | Cloudflare | **규격에 있음** | **Draft** |
| 스캔 + 서명 + 카탈로그 | **NVIDIA** | **있음** | **구현** |

### Cloudflare RFC — 규격으로 풀려는 시도

`cloudflare/agent-skills-discovery-rfc`(351)의 17개 절 중 둘이 이 문제를 다룬다([6.6](../part6/06-cloudflare.md)).

- Integrity and Verification
- Security Considerations

**무결성 검증을 규격에 넣은 유일한 제안이다.** Google의 `index.json`은 `entrypoint`로 raw 깃허브 URL을 주는데, 그 URL의 내용이 바뀌어도 알 수 없다.

스타 351개이고 Draft 상태다. 마지막 갱신이 2026-03-12다.

### NVIDIA 파이프라인 — 구현된 유일한 것

| 단계 | 하는 일 |
|---|---|
| 스캔 | 71개 패턴 (`SkillSpector`) |
| 평가 | — |
| **서명** | 무결성 보장 |
| 게시 | `NVIDIA/skills`(399개) |

**규격은 Draft인데 한 회사의 파이프라인은 돌아간다.** 다만 그 파이프라인은 NVIDIA 카탈로그에만 적용된다. 생태계 전체에는 26.1%와 5.2%가 그대로 남아 있다.

### 수요는 스캐너 쪽에 있다

| 저장소 | 스타 |
|---|---|
| `NVIDIA/SkillSpector` (스캐너) | 19,226 |
| `NVIDIA/skills` (검증된 카탈로그) | 3,512 |

**스캐너가 카탈로그보다 5.5배 주목받았다.**

사용자가 남이 고른 것을 받기보다 **자기가 고른 것을 검사하려 한다**는 뜻으로 읽힌다. 카탈로그는 범위가 제한되고(NVIDIA 제품), 스캐너는 어디서 가져온 스킬에든 쓸 수 있다.

## 설치 전 점검표

실무적으로 쓸 수 있는 순서다. 위에서 아래로 갈수록 비용이 늘어난다.

### 1단계 — 메타데이터 (1분)

| 확인 | 왜 |
|---|---|
| README 첫 단락 | 폐기, 이전 표시가 여기만 있다([9.1](01-star-traps.md)) |
| 마지막 푸시 | 지식형, 보안이면 결정적 |
| 라이선스 | AGPL, CC-BY-SA, NOASSERTION 확인([9.4](04-licensing.md)) |
| 계정 종류 | 조직 계정인가 개인 계정인가 |

### 2단계 — 구성 (5분)

| 확인 | 왜 |
|---|---|
| `scripts/`가 있나 | 코드가 실행된다. 검증 비용이 크게 늘어난다 |
| `hooks/`가 있나 | **판단 없이 항상 실행된다** |
| MCP 서버 설정이 있나 | 외부 접근 권한이 생긴다 |
| `SKILL.md` 개수 | 많으면 읽을 수 없다 |
| 네트워크 접근 | `compatibility`에 적혀 있는가 |

**`hooks/`와 MCP 설정이 가장 중요하다.** 스킬 본문은 트리거돼야 작동하지만 훅은 항상 돈다.

### 3단계 — 내용 (스킬 수에 비례)

| 확인 | 무엇을 찾나 |
|---|---|
| `description`의 범위 | 과도하게 넓은가. "항상 먼저 쓰라"가 있는가 |
| 본문의 외부 접근 지시 | 어디로 무엇을 보내라고 하는가 |
| 스크립트의 네트워크 호출 | 어디에 접속하는가 |
| 비밀값 접근 | 환경변수, 키 파일을 읽는가 |

**스킬이 10개를 넘으면 이 단계를 사람이 할 수 없다.** 도구가 필요하다.

### 4단계 — 스캔

```bash
# SkillSpector
# SARIF 출력이므로 기존 CI에 붙는다
```

베이스라인으로 알려진 발견을 억제하면 재스캔에서 **새 문제만** 보인다. 이 기능이 없으면 오탐에 묻혀 아무도 보지 않는다.

## 만드는 쪽의 책임

스킬을 공개하는 사람이 할 수 있는 것들이다.

| 항목 | 효과 |
|---|---|
| `compatibility`에 외부 의존성을 적는다 | 설치자가 무엇이 필요한지 안다 |
| 스크립트의 네트워크 호출을 문서화한다 | 검증 비용을 줄인다 |
| 마크다운 전용이면 그렇다고 적는다 | 공급망 위험이 낮다는 신호 |
| 제거 경로를 제공한다 | 남은 파일이 트리거 충돌을 일으킨다 |
| 버전을 관리한다 | 무엇이 설치됐는지 추적 가능 |
| 라이선스를 명확히 한다 | NOASSERTION은 검토 부담 |

**마크다운 전용을 명시한 사례**가 있다. `wanshuiyin/Auto-claude-code-research-in-sleep`(16,931)이 "경량 마크다운 전용"을 설명에 적는다([8.6](../part8/06-research.md)).

| | 마크다운 전용 | 스크립트 포함 |
|---|---|---|
| 공급망 위험 | 낮다 | 높다 |
| 검증 | 읽으면 끝 | 코드를 읽어야 함 |
| 실행 일관성 | 낮다 | 높다 |

**제거 경로를 제공한 사례**는 `epoko77-ai/im-not-ai`다 — `uninstall.sh`가 있다([8.5](../part8/05-writing.md)). 설치 스크립트를 주는 저장소는 많고 제거 스크립트를 주는 경우는 드물다.

## 이 책이 할 수 없는 것

정직하게 적어 둔다.

**이 책은 리뷰한 저장소를 스캔하지 않았다.** `SkillSpector`를 돌리지 않았고, 스킬 내용을 보안 관점으로 읽지 않았다. 리뷰는 구조와 설계를 봤다.

**26.1%와 5.2%를 특정 저장소에 적용할 수 없다.** 전체 분포이고, Trail of Bits 같은 전문 회사의 저장소가 평균과 같다고 볼 근거가 없다.

그래서 이 책의 "골라 쓰는 기준" 표들은 **설계 품질에 대한 판단이고 안전성 보증이 아니다.** 설치 전에 직접 검사하는 것을 권하고, 그 권고를 각 도메인 장에 적었다.

갱신 규칙에 이 항목을 넣는다 — 다음 수집 때 상위 저장소에 스캐너를 돌리는 것을 과제로 남긴다([9.6](06-update-policy.md)).
