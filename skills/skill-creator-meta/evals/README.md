# 이 스킬 자체의 평가

**자극은 정의했고 결과는 아직 측정하지 않았다.** 이 파일은 그 사실을 숨기지 않으려고 있다.

이 스킬은 쓰는 사람에게 세 팔 측정을 요구한다. 그래서 자기 평가 결과가 없다는 것이 약점이고, 그 약점을 적어 두는 것이 이 저장소의 방식이다. 측정하지 않은 것을 측정한 것처럼 쓰지 않는다.

## 왜 아직 측정하지 않았는가

이 스킬의 산출물은 **다른 스킬**이다. 채점 대상이 "생성된 스킬의 품질"이고, 그 품질은 생성된 스킬을 또 세 팔로 돌려야 나온다. 자극 5개를 다 돌리면 측정이 2단으로 중첩된다.

대신 **대리 지표**로 측정할 수 있게 자극을 짰다. 생성된 `SKILL.md`를 `scripts/validate_skill.py`에 넣어 WARN 개수를 세는 것이다. 이것이 품질의 대리 지표라는 점은 분명히 한다.

| 재는 것 | 못 재는 것 |
|---|---|
| 체크리스트 항목이 산출물에 들어갔는가 | 그 스킬이 실제로 일을 잘하는가 |

## 자극

`evals.json`에 다섯 개를 정의했다. 세 종류를 섞었다.

| id | 종류 | 노리는 것 |
|---|---|---|
| 1-repeated-task | 전형적인 성공 | 만들어야 할 요청에서 스킬이 나오는가 |
| 2-vague-request | 재료 부족 | 네 가지를 묻는가, 추측으로 채우는가 |
| 3-should-not-build | **개입하면 안 되는 입력** | 만들지 말라고 하는가 |
| 4-duplicate-exists | **개입하면 안 되는 입력** | 기존 저장소를 가리키는가 |
| 5-two-skills | 범위 분리 | 접속사를 보고 둘로 나누는가 |

3번과 4번이 이 스킬의 변별력이 걸린 자극이다. 0단계가 작동하는지를 거기서 본다.

## 돌리는 방법

```bash
# A 스킬  — 이 스킬을 켠 세션
# B 기준선 — 스킬 없이 같은 프롬프트
# C 조악한 대조군 — 아래 두 줄짜리 스킬만 켠 세션
```

C는 이렇게 만든다.

```markdown
---
name: crude-arm
description: 스킬 만들어줘, 스킬 생성, SKILL.md 작성, create a skill
---
사용자의 요청을 받아 SKILL.md 를 만든다. 프런트매터에 name 과 description 을 넣는다.
```

자극마다 독립 세션으로 돌리고, 채점은 만든 사람이 하지 않는다.
