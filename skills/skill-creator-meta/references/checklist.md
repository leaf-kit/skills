# 체크리스트

`scripts/` 를 못 쓰는 환경에서 이 파일만으로 0단계부터 공개까지 갈 수 있게 적었다. 스크립트를 쓸 수 있으면 0단계와 6단계는 스크립트가 대신한다.

각 항목에 **왜**가 붙어 있다. 왜를 읽고 근거를 적을 수 있으면 건너뛴다. 체크표만 채우는 것은 이 저장소가 반대하는 일이다.

---

## 0단계 — 만들지 않을 이유

| # | 질문 | 예라면 |
|---|---|---|
| 0.1 | 이 일을 앞으로 **세 번 이상** 할 것인가 | 아니면 프롬프트로 쓴다 |
| 0.2 | 조건 없이 **항상** 적용되는가 | `CLAUDE.md` 같은 지침 파일로 간다 |
| 0.3 | 안 돌면 **사고**가 나는가 | 훅으로 간다. 훅은 판단 없이 항상 실행된다 |
| 0.4 | 외부 시스템 **접근 권한**이 필요한가 | MCP 서버 쪽을 먼저 본다 |
| 0.5 | 이미 **70% 이상** 맞는 것이 있는가 | 포크해서 고친다 |

0.5를 확인하는 순서.

1. `part11/01-taxonomy.md`에서 8개 대분류 중 어디에 속할지 고른다.
2. 그 대분류의 장을 열어 소분류를 훑는다.
3. 후보 저장소의 `SKILL.md`를 **실제로 읽는다.** README만 읽고 "없다"고 판단한 적이 이 저장소에도 여러 번 있었다.

**중복인데도 만들어야 하면 이유를 적는다.** 조건이 다른가(언어, 플랫폼, 규모), 설계 축이 다른가. 둘 다 아니면 기존 저장소에 기여한다.

---

## 1단계 — 범위

| # | 항목 | 왜 |
|---|---|---|
| 1.1 | 한 문장으로 적었는가 | 접속사가 들어가면 스킬이 둘 이상이다 |
| 1.2 | **결핍**으로 적었는가 | "무엇을 한다"보다 "없으면 무엇이 안 되는가"가 범위를 좁힌다 |
| 1.3 | 걸려야 할 표현 **3개**를 받았는가 | `description`의 재료 |
| 1.4 | 걸리면 안 될 표현 **2개**를 받았는가 | 제외 조건의 재료. 안 물으면 안 나온다 |
| 1.5 | 출력 모양을 받았는가 | 본문의 절반이 여기서 나온다 |
| 1.6 | 애매할 때 어느 쪽인지 받았는가 | 두 방향 실패의 비용 비교 |

**못 받은 것은 `[확인 필요: ...]`로 남긴다.** 추측으로 채우면 그럴듯한 일반론이 된다.

## 2단계 — description

| # | 항목 |
|---|---|
| 2.1 | 무엇을 하는가가 한 문장으로 있다 |
| 2.2 | 언제 쓰는가가 있다. 모드가 둘이면 둘 다 |
| 2.3 | 키워드가 **한국어와 영어 양쪽**으로 있다 |
| 2.4 | 밀어붙이는 지시가 있다 ("~하면 반드시 적용한다") |
| 2.5 | **제외 조건**이 있다 ("반대로 ~에는 쓰지 않는다") |
| 2.6 | 형제 스킬이 있으면 **이름으로** 가리켰다 |
| 2.7 | 절차 요약이 들어가지 않았다 |
| 2.8 | "가장 강력한", "완벽하게" 같은 과장이 없다 |
| 2.9 | 1,024자 이하다 |

2.5가 가장 많이 빠진다. 2.6은 제외만 적으면 "내 일이 아니다"에서 끝나므로 대안을 적어 경계를 그리는 것이다.

## 3단계 — 본문

| # | 항목 | 왜 |
|---|---|---|
| 3.1 | **과잉 적용 방지 절이 있다** | 없으면 무언가 해야 한다고 판단한다 |
| 3.2 | 대상이 아닌 것을 **셋 이상** 적었다 | 하나나 둘이면 범위가 안 그려진다 |
| 3.3 | **두 방향 실패의 비용을 비교**해 적었다 | 측정에서 가장 큰 차이를 만든 한 줄 |
| 3.4 | 금지마다 **이유**가 붙어 있다 | 금지만 있으면 충돌 때 무엇을 포기할지 모른다 |
| 3.5 | 출력 형식을 **예시로** 보여 줬다 | 설명만 하면 형식이 흔들린다 |
| 3.6 | 대문자 강조가 셋 미만이다 | 대문자 자리마다 설명이 빠져 있다 |
| 3.7 | 500줄 이하다 | 넘으면 스킬 둘이 섞여 있을 가능성 |
| 3.8 | **"보지 않은 것"을 보고하게 했다** | 실패를 숨기면 결과를 과신한다 |

### 과잉 적용 방지 절의 틀

```markdown
### 과하게 하지 않는다

이 스킬의 실패 방식은 두 가지다. (놓치는 것), 그리고 (멀쩡한 것을
건드리는 것)이다. **두 번째가 더 나쁘다.** (이유)

아래는 대상이 아니다.
- (구체적으로 셋 이상)

판단이 애매하면 (어느 쪽으로). (애매한 것을 X하는 비용이 멀쩡한 것을
Y하는 비용보다 작다.)
```

## 4단계 — 번들

| # | 항목 |
|---|---|
| 4.1 | 항상 필요한 것만 본문에 남겼다 |
| 4.2 | 조건부 내용은 `references/`에 있다 |
| 4.3 | **참조 파일마다 읽기 조건을 적었다** |
| 4.4 | 본문에서 가리키지 않는 번들 파일이 없다 |
| 4.5 | 입출력이 정해진 일은 `scripts/`로 옮겼다 |
| 4.6 | 스크립트 출력이 JSON이다 |
| 4.7 | 오류 메시지가 **다음 행동**을 가리킨다 |
| 4.8 | **스크립트가 자기 한계를 출력에 적는다** |
| 4.9 | 파싱 실패나 건너뛴 것을 따로 낸다 |

4.3의 차이.

```
나쁨: 자세한 내용은 references/patterns.md 를 참고한다.
좋음: 판정이 애매한 경우가 나오면 references/patterns.md 를 펼친다.
```

4.8의 차이.

```python
"note": "이름 기반 근사다. 간접 호출로 덮인 경우를 놓쳤다고 보고할 수 있다."
```

## 5단계 — 평가

| # | 항목 |
|---|---|
| 5.1 | 성공 케이스가 있다 |
| 5.2 | 재료나 정보가 부족한 케이스가 있다 |
| 5.3 | **개입하면 안 되는 케이스가 있다** |
| 5.4 | 프롬프트가 실제 사용자 말투다 |
| 5.5 | **양성 어서션이 섞여 있다** |
| 5.6 | 동어반복 어서션이 없다 |
| 5.7 | **사실 정확성을 검사하는 어서션이 있다** |
| 5.8 | **기준선** 팔을 돌렸다 |
| 5.9 | **조악한 대조군** 팔을 돌렸다 |
| 5.10 | 자극이 5개 이상이거나, **검정력 부족을 결과에 적었다** |
| 5.11 | 채점을 만든 사람이 하지 않았다 |
| 5.12 | 채점자에게 **어서션 자체를 비판하라고** 지시했다 |

자세한 내용은 `eval-design.md`에 있다.

## 6단계 — 공개

| # | 항목 | 왜 |
|---|---|---|
| 6.1 | `name`이 디렉터리 이름과 같다 | 다르면 로드되지 않는다 |
| 6.2 | 프런트매터에 `license`가 있다 | |
| 6.3 | **스킬 디렉터리 안에 `LICENSE` 파일이 있다** | 스킬은 디렉터리 단위로 복사된다 |
| 6.4 | 저장소 루트에 `LICENSE`가 있다 | |
| 6.5 | 깨끗한 설치에서 한 번 돌려 봤다 | 개발 환경에만 있는 의존성을 잡는다 |
| 6.6 | `README`에 **못 하는 것**을 적었다 | 잘못된 기대를 막는다 |
| 6.7 | 평가 결과와 **한계**를 같이 적었다 | 검정력 부족을 숨기지 않는다 |
| 6.8 | 네트워크 호출과 비밀값 접근을 밝혔다 | 쓰는 사람이 판단할 수 있게 |
| 6.9 | `hooks/`가 있으면 **강조해서** 알렸다 | 훅은 판단 없이 항상 실행된다 |
| 6.10 | 개인정보, 사내 경로, 토큰이 없다 | 한 번 올라가면 히스토리에 남는다 |
| 6.11 | 가운데점을 쉼표로 바꿨다 | 이 저장소의 문체 규칙 |
| 6.12 | 안 열리는 `**` 강조가 없다 | 닫는 `**` 앞 구두점 + 뒤 한글 조사 |

**6.1부터 6.9까지 통과하지 못한 스킬은 공개하지 않는다.** 개인용으로 쓰는 것이 맞다.
