# 스킬 만들기

**Anthropic 공식 `skill-creator`를 대체하지 않는다.** 공식 스킬은 뼈대를 만들고 `description`을 다듬는 데 강하다. 이 스킬은 거기에 두 가지를 더한다. 둘 다 이 저장소가 생태계를 리뷰하고 직접 측정하면서 나온 것이다.

| 보통의 생성기 | 이 스킬 |
|---|---|
| 요청을 받으면 바로 만든다 | **만들지 않을 이유를 먼저 확인한다** |
| 평가를 선택 사항으로 둔다 | **조악한 대조군까지 요구한다** |

생태계에 중복이 폭발한 이유가 첫 줄이고([9.5](../../part9/05-saturation.md)), 설계 의도와 실제 기여가 다른 것을 평가 없이는 모른다는 것이 둘째 줄이다([10.2](../../part10/02-validation.md)).

공식 스킬을 이미 쓰고 있으면 **0단계와 5단계만 이 문서에서 가져와도 된다.** 그 두 단계가 이 스킬의 전부다.

---

## 0단계 — 만들지 않을 이유를 먼저 본다

**건너뛰지 않는다.** 이 단계가 이 생성기의 핵심이다.

```bash
python3 scripts/check_duplicate.py "하려는 일을 한 문장으로"
```

스크립트가 없으면 `references/checklist.md`의 0단계 표를 쓴다.

다섯 가지를 확인한다. 하나라도 걸리면 **만들지 않는다.**

| 확인 | 걸리면 |
|---|---|
| 한 번만 쓸 일인가 | 프롬프트로 쓴다 |
| 조건 없이 **항상** 적용되는가 | 지침 파일에 둔다. 스킬은 안 불리는 날에 빠진다 |
| 안 돌면 **사고**가 나는가 | **훅**으로 간다. 판단이 개입하면 안 된다 |
| 외부 시스템 접근이 필요한가 | MCP 서버 쪽을 먼저 본다 |
| 이미 70% 이상 맞는 것이 있는가 | **포크해서 고친다** |

마지막 줄이 가장 자주 무시된다. **찾는 비용이 만드는 비용보다 커서 다들 만든다.** 이 저장소의 분류 데이터가 그 비용을 낮추려고 있다.

중복을 발견했는데도 만들어야 하면 **이유를 적는다.** 조건이 다른가(언어, 플랫폼, 규모), 설계 축이 다른가. 둘 다 아니면 기존 저장소에 기여한다.

## 1단계 — 의도를 한 문장으로

**결핍에서 출발한다.** "무엇을 하는 스킬인가"보다 "이게 없으면 무엇이 안 되는가"가 범위를 좁힌다.

```
약한 답: 코드를 리뷰한다
나은 답: 우리 팀 컨벤션을 모르는 사람이 올린 PR에서 컨벤션 위반을 찾아낸다
```

**접속사를 센다.** "그리고", "또는"이 들어가면 스킬이 둘 이상이다.

```
접속사 3개 → 스킬 3개
  컨벤션 위반을 찾고, 보안을 점검하고, 테스트 누락을 알려 준다
접속사 0개 → 스킬 1개
```

그리고 네 가지를 사용자에게 **한 묶음으로** 묻는다. 추측해 채우면 그럴듯한 일반론이 나온다.

| 질문 | 왜 |
|---|---|
| 걸려야 할 사용자 표현 세 개 | `description`의 재료 |
| **걸리면 안 될 표현** 두 개 | 제외 조건의 재료 |
| 출력이 어떤 모양인가 | 본문의 절반이 여기서 나온다 |
| 판단이 갈릴 때 어느 쪽으로 | **두 방향 실패의 비용 비교** |

답이 없으면 추측을 사실처럼 쓰지 말고 `[확인 필요: ...]`로 남긴다.

## 2단계 — description

**다섯 요소를 다 넣는다.** 하나라도 빠지면 트리거가 샌다.

| 요소 | 내용 |
|---|---|
| 1. 무엇을 하는가 | 한 문장 |
| 2. 언제 쓰는가 | 상황. 모드가 둘이면 둘 다 |
| 3. 키워드 | **한국어와 영어를 같이.** 사용자가 쓰는 말 |
| 4. 밀어붙이는 지시 | "~하면 반드시 적용한다" |
| 5. **제외 조건** | "반대로 ~에는 쓰지 않는다" |

5번이 가장 많이 빠진다. 제외 조건은 **과잉 트리거를 줄이고 형제 스킬과 경계를 긋는다.**

**형제 스킬이 있으면 이름으로 가리킨다.** 제외만 적으면 "내 일이 아니다"에서 끝나고, 대안을 적으면 경계가 그려진다.

```
반대로 전체 코드베이스 감사에는 쓰지 않는다. 그건 security-audit 이 한다.
```

### 쓰지 말 것

| 금지 | 왜 |
|---|---|
| 절차 요약 | `description`은 **언제** 쓰는지를 적는 자리다. 어떻게는 본문에 있다 |
| "가장 강력한", "완벽하게" | 트리거에 기여하지 않고 과잉 트리거를 부른다 |
| "다양한 작업에 유용한" | 범위를 넓히는 게 아니라 지운다 |

**매끄럽게 읽히지 않아도 된다.** 이 필드는 산문이 아니라 트리거 신호의 집합이다.

## 3단계 — 본문

### 반드시 넣을 절 — 과잉 적용 방지

**이 절이 없으면 스킬이 과하게 작동한다.** "하라"는 지시로만 채우면 무언가 해야 한다고 판단한다.

세 가지를 적는다.

```markdown
### 과하게 하지 않는다

이 스킬의 실패 방식은 두 가지다. (놓치는 것), 그리고 (멀쩡한 것을
건드리는 것)이다. **두 번째가 더 나쁘다.** (이유)

아래는 대상이 아니다.
- (구체적으로 셋 이상)

판단이 애매하면 (어느 쪽으로). (애매한 것을 X하는 비용이 멀쩡한 것을
Y하는 비용보다 작다.)
```

마지막 줄이 핵심이다. **두 방향 실패의 비용을 비교해 적는다.** 측정에서 이 한 줄이 가장 큰 차이를 만들었다([10.2](../../part10/02-validation.md)).

### 이유를 적는다

금지 목록은 적용 범위를 스스로 정하지 못한다. 충돌 상황에서 무엇을 포기할지 알려 주지 않는다.

```
금지형: 표 쓰지 마.
이유형: 이 글은 슬랙에 붙인다. 슬랙에서 마크다운 표는 깨진다.
        그래서 비교할 항목이 있으면 짧은 문단으로 보여 준다.
```

**대문자 강조를 쓰는 자신을 발견하면 노란불이다.** 그 자리에 설명이 빠져 있다는 신호다.

### 분량

| 상태 | 판단 |
|---|---|
| 100줄 아래 | 정상. 공식 스킬 다수가 여기 |
| 100~300줄 | 괜찮다 |
| 500줄 접근 | 참조 파일로 내린다 |
| 500줄 초과 | **스킬 둘이 섞여 있을 가능성** |

**줄 수와 토큰은 다르다.** 긴 산문을 줄바꿈 없이 쓰면 줄 수는 적고 토큰은 많다. 500줄 아래인데 비싸면 줄 길이를 본다.

## 4단계 — 번들

### 무엇을 어디에

| 질문 | 답 |
|---|---|
| 이 스킬이 트리거될 때 **항상** 필요한가 | 본문 |
| 조건부로 읽나 | `references/` |
| 읽지 않고 **실행**만 하나 | `scripts/` |
| 출력물에 넣는 **재료**인가 | `assets/` |

**참조 파일에는 읽기 조건을 반드시 적는다.** 조건이 없으면 항상 읽거나 한 번도 안 읽는다.

```
나쁨: 자세한 내용은 references/patterns.md 를 참고한다.
좋음: 판정이 애매한 경우가 나오면 references/patterns.md 를 펼친다.
```

### 스크립트를 쓸 때

**입력과 출력이 정해지면 코드로 쓴다.** 정해지지 않으면 판단이다.

세 가지를 지킨다.

| 항목 | 내용 |
|---|---|
| 출력은 JSON | 에이전트가 필요한 값만 꺼내 쓴다. 산문은 전부 읽어야 한다 |
| 오류 메시지가 **다음 행동**을 가리킨다 | "Invalid PDF"가 아니라 "스캔본일 수 있다. X를 쓰세요" |
| **한계를 출력에 적는다** | 근사를 근사라고 적지 않으면 에이전트가 사실로 보고한다 |

```python
"note": "이름 기반 근사다. 간접 호출로 덮인 경우를 놓쳤다고 보고할 수 있다."
```

**실패를 숨기지 않게 한다.** 파싱 실패나 건너뛴 파일을 따로 내고, 본문에 "보지 않은 것" 절을 둬서 보고하게 한다.

## 5단계 — 평가

**여기서 멈추지 않는다.** 생태계 대부분이 평가 없이 배포되고, 그래서 설계 의도와 실제 기여가 다른 것을 모른다.

여기서는 골격만 적는다. 자극을 실제로 짜거나 어서션을 쓰는 단계에 들어가면 `references/eval-design.md`를 펼친다.

### 테스트 케이스 — 세 종류를 섞는다

| # | 케이스 | 재는 것 |
|---|---|---|
| 1 | 전형적인 성공 | 제 일을 하는가 |
| 2 | 재료나 정보가 부족 | 멈추고 묻는가, **지어내는가** |
| 3 | **개입하면 안 되는 입력** | 과하게 하지 않는가 |

**3번이 가장 설계하기 어렵고 가장 값이 나간다.** 측정에서 변별력이 여기서 나왔다.

프롬프트는 **실제 사용자가 쓸 말**로 쓴다. 파일 경로, 사연, 구어체가 섞여야 한다. 깔끔하게 다듬으면 테스트가 안 된다.

### 어서션 — 네 가지 함정을 피한다

| 함정 | 증상 | 고치는 법 |
|---|---|---|
| **전부 부정형** | "아무것도 안 함"이 만점 | **양성 어서션을 섞는다** |
| **동어반복** | 스킬만 통과할 수 있는 구조 | 폐기한다. 측정이 아니다 |
| **사실 정확성 미검사** | 지어낸 근거가 통과 | "보고한 값이 실제 동작과 일치한다" |
| **우회 가능** | 재분류하면 상한을 넘김 | 세는 단위를 정의한다 |

네 가지 다 실제 측정에서 나왔다.

### 세 팔로 돌린다

| 팔 | 답하는 질문 |
|---|---|
| 스킬 적용 | — |
| **기준선** (스킬 없음) | 스킬이 기여하는가 |
| **조악한 대조군** (두 줄짜리 스킬) | **설계가 기여하는가** |

**세 번째를 빠뜨리지 않는다.** 두 줄로 같은 결과가 나오면 본문 300줄과 스크립트는 과잉이다. 비용은 토큰 세 번이다.

### 결과를 읽는다

| 상황 | 뜻 |
|---|---|
| 스킬만 통과 | 변별력 있음 |
| 양쪽 다 통과 | **변별력 없음** — 어서션을 고친다 |
| **기준선만 통과** | **스킬이 해를 끼친다** |
| 스킬 ≈ 조악한 대조군 | 설계가 기여하지 않는다. 단순화한다 |
| **자극 5개 미만** | **검정력 부족.** 합격도 실패도 아니다 |

마지막 줄을 결과에 **반드시 적는다.** 자극 3개로 "100% 대 69%"를 유의하다고 쓸 수 없다.

### 채점은 남에게 맡긴다

만든 사람이 채점하면 관대해진다. 그리고 **어서션 자체를 비판하라고 지시한다.** 통과했는데 변별력 없는 항목, 아무도 검사하지 않는 중요한 결과를 찾게 한다.

## 6단계 — 검증과 공개

```bash
python3 scripts/validate_skill.py <스킬 경로>
```

규격 준수와 **이 저장소의 원칙**을 같이 검사한다. 규격만 보는 `skills-ref validate`와 다른 점이다.

공개 체크리스트는 `references/checklist.md`에 있다. 요약하면 셋이다.

**라이선스를 세 곳에 둔다.** 루트 `LICENSE`, 스킬별 `LICENSE.txt`, 프런트매터 `license`. 스킬은 디렉터리 단위로 복사되므로 루트에만 두면 떨어진다.

**한계를 `README`에 적는다.** 무엇을 못 하는지 적으면 쓰는 사람이 잘못된 기대를 안 한다.

**공개하는 쪽의 책임을 진다.** 스크립트의 네트워크 호출과 비밀값 접근을 밝히고, `hooks/`가 있으면 강조한다. 훅은 판단 없이 항상 실행된다.

## 만들면서 지키는 것

**확인하지 않은 것을 확인한 것처럼 쓰지 않는다.** "없다"고 쓰기 전에 실제로 본다. 없는 것은 눈에 띄지 않아서 확인이 소홀해진다.

**사용자가 준 재료를 고치지 않는다.** 사용자의 사례나 표현을 "더 좋게" 다듬지 않는다.

**체크리스트를 통과하지 못한 스킬은 공개하지 않는다.** 개인용으로 쓰는 것이 맞다.

## 참고 파일

- `references/checklist.md` — Python 을 쓸 수 없거나 단계를 빠뜨렸는지 확인할 때 펼친다. 0단계부터 공개까지 전부 들어 있다.
- `references/eval-design.md` — 5단계에 들어가면 펼친다. 어서션 함정 네 가지, 세 팔 구성, 검정력 판단이 들어 있다.
- `assets/template/` — 1단계를 마쳤으면 복사해서 시작한다. `SKILL.md`, `evals/evals.json`, `LICENSE` 뼈대가 들어 있다.
- `evals/` — 이 스킬 자체의 평가다. 자극은 정의했고 **결과는 아직 측정하지 않았다.** `evals/README.md` 에 그 사실을 적었다.
