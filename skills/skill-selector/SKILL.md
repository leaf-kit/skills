# 스킬 고르기

이 저장소는 에이전트 스킬 생태계의 지도다. 이 스킬은 **그 지도를 읽어 사용자의 상황에 맞는 답을 내는** 절차다.

## 먼저 알아야 할 것

**스타수는 품질이 아니라 주목을 잰다.** 이 저장소의 모든 순위는 그 전제 위에 있다. 스타수로 추천하지 않는다.

**숫자에는 날짜가 붙는다.** 데이터는 월 단위 스냅샷이고, 수집일이 `data/snapshots/<YYYY-MM>/meta.json`에 있다. 답할 때 수집일을 함께 말한다.

## 절차

### 1. 사용자의 상황을 한 문장으로 좁힌다

"좋은 스킬 추천해 줘"에는 답할 수 없다. 셋 중 무엇인지 판별한다.

| 질문 | 다음 단계 |
|---|---|
| **무엇을 하려는가** (작업이 정해졌다) | 2단계로 |
| **어떤 카테고리가 있는가** (탐색 중이다) | `part11/01-taxonomy.md` 의 전체 지도를 보여 준다 |
| **이 스킬을 써도 되는가** (후보가 있다) | 4단계로 |

작업이 모호하면 **한 번만** 묻는다. "어떤 작업을 에이전트에게 맡기려 하시나요?" 답이 없으면 카테고리 지도를 보여 주고 끝낸다.

### 2. 카테고리를 찾는다

```bash
python3 scripts/query.py --search "코드 리뷰"
python3 scripts/query.py --category A3
python3 scripts/query.py --list
```

스크립트가 없으면 `references/category-map.md`를 읽는다.

분류 축은 **에이전트가 무엇을 대상으로 일하는가**다. 8개 대분류, 36개 소분류로 나뉜다.

| 코드 | 대분류 |
|---|---|
| A | 코드 |
| B | 문서와 글 |
| C | 시각물 |
| D | 플랫폼과 인프라 |
| E | 사람과 조직의 일 |
| F | 에이전트 자신 |
| G | 스킬 자신 |
| H | 경계 (스킬이 부속인 저장소) |

### 3. 해당 장을 읽고 추천한다

소분류를 찾았으면 그 장을 읽는다. 장마다 **"언제 쓰나"** 열이 있다.

| 대분류 | 장 |
|---|---|
| A | `part11/02-code.md` |
| B | `part11/03-writing.md` |
| C | `part11/04-visual.md` |
| D | `part11/05-platform.md` |
| E | `part11/06-work.md` |
| F | `part11/07-agent.md` |
| G | `part11/08-meta.md` |
| H | `part11/09-boundary.md` |
| **보안** | `part11/10-security.md` (A3과 G3을 묶은 장) |

깊은 리뷰가 필요하면 8부(`part8/`)로 넘어간다. 각 장이 링크를 갖고 있다.

### 4. 추천 전에 네 가지를 확인한다

**스타수만 보고 추천하지 않는다.** 이 저장소의 리뷰에서 반복 확인된 함정이다.

| 확인 | 왜 | 어디서 |
|---|---|---|
| **마지막 푸시** | 지식형은 낡으면 **없는 것보다 나쁘다** | `data/snapshots/latest/stars.tsv` |
| **유형** | 실행형/지식형/방법론형에 따라 수명이 다르다 | `part4/02-three-types.md` |
| **라이선스** | AGPL, CC-BY-SA, NOASSERTION은 제약이 있다 | `part9/04-licensing.md` |
| **폐기 여부** | 메타데이터에 없다. README 첫 단락을 본다 | `part9/01-star-traps.md` |

마지막 항목이 중요하다. `openai/skills`(27,856)는 폐기됐는데 톱 30에 있다. **폐기 사실은 설명이나 토픽에 없고 README 첫 단락에만 있다.**

### 5. 설치 전 검사를 안내한다

```
분석한 31,132개 스킬 중 26.1%가 취약점을 포함하고 5.2%가 악의적 의도로 보인다.
(출처: NVIDIA/SkillSpector)
```

**스킬은 설치하는 순간 사용자의 권한으로 움직인다.** 추천할 때 `NVIDIA/SkillSpector`로 스캔하라고 한 줄 덧붙인다.

번들에 아래가 있으면 특히 강조한다.

| 발견 | 왜 |
|---|---|
| `hooks/` | **판단 없이 항상 실행된다** |
| MCP 서버 설정 | 외부 접근 권한이 생긴다 |
| `scripts/` | 코드가 실행된다. 검증 비용이 커진다 |

## 답하는 형식

### ① 추천 (최대 3개)

저장소마다 네 줄로 적는다.

```
`cloudflare/security-audit-skill` (23,894★, 2026-09-14 푸시, MIT)
언제: 코드베이스를 통째로 감사할 때
왜: 스킬 1개 + 참조 14개 구조라 트리거 충돌이 없다
확인: 평가(기준선 비교)가 없다
```

**세 개를 넘기지 않는다.** 선택지를 늘리면 사용자의 문제가 커진다.

### ② 고르는 기준 한 줄

상황이 갈리면 그 기준을 적는다.

```
전체 감사면 첫째, 단계별 제어가 필요하면 둘째를 쓴다.
```

### ③ 설치 전 확인

위 5단계의 내용을 한두 줄로.

### ④ 근거

**어느 장을 읽고 답했는지 적는다.** 사용자가 직접 확인할 수 있어야 한다.

```
근거: part11/10-security.md, part8/01-security.md (수집일 2026-10-04)
```

## 하지 않는 것

**없는 저장소를 지어내지 않는다.** 이 저장소의 데이터에 없으면 "수집 데이터에 없다"고 말한다. 150위 밖은 기계 판정을 하지 않았으므로 누락이 있을 수 있다는 점도 함께 적는다.

**스타수를 품질로 바꿔 말하지 않는다.** "가장 인기 있는"은 괜찮고 "가장 좋은"은 아니다.

**확인하지 않은 것을 확인한 것처럼 적지 않는다.** 요약 리뷰로만 다룬 저장소는 그렇다고 밝힌다.

**스킬을 만드는 법을 여기서 설명하지 않는다.** 3부(`part3/`)로 보낸다.
