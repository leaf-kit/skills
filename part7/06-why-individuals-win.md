# 7.6 개인이 빅테크를 앞지르는 이유

트랙 A 상위 5개 중 4개가 개인 또는 소규모 조직이다. 규격을 만든 Anthropic이 2위다.

| # | 스타 | 저장소 | 주체 |
|---|---|---|---|
| 1 | 294,779 | `obra/superpowers` | 개인 |
| 2 | 179,497 | `anthropics/skills` | 빅테크 |
| 3 | 152,808 | `DietrichGebert/ponytail` | 개인 |
| 4 | 100,746 | `addyosmani/agent-skills` | 개인 |
| 5 | 99,281 | `nexu-io/open-design` | 소규모 조직 |

(수집 날짜: 2026-10-04)

`anthropics/skills`를 뺀 빅테크 공식 저장소는 전부 1위의 10% 아래다.

| 저장소 | 스타 | 1위 대비 |
|---|---|---|
| `openai/skills` | 27,856 | 9% |
| `google/skills` | 20,875 | 7% |
| `dotnet/skills` | 5,543 | 2% |
| `NVIDIA/skills` | 3,512 | 1% |
| `microsoft/skills` | 3,075 | 1% |
| `cloudflare/skills` | 2,974 | 1% |
| `github/copilot-plugins` | 369 | 0.1% |

이 장은 왜 그런지를 정리한다. 6부와 7부의 리뷰에서 나온 관찰을 모은다.

## 이유 1 — 공식 저장소는 제품을 판다

빅테크 공식 번들의 구성 축이 거의 전부 **자사 제품**이다.

| 저장소 | 구성 | 비중 |
|---|---|---|
| `google/skills` | Google Cloud | 155개 중 136개 (88%) |
| `microsoft/skills` | Azure | 205개 전부 |
| `cloudflare/skills` | Cloudflare 제품 | 16개 전부 |
| `NVIDIA/skills` | NVIDIA 제품 | 399개 |

**Azure를 쓰지 않으면 `microsoft/skills` 205개가 전부 쓸 데가 없다.** 잠재 사용자가 그 제품의 사용자로 제한된다.

개인 저장소는 그런 제약이 없다. `ponytail`은 "모든 코딩 작업"에 걸리고, `humanizer`는 모든 글에, `i-have-adhd`는 모든 출력에 걸린다([7.3](03-single-purpose.md)).

예외가 이 설명을 뒷받침한다. `cloudflare/security-audit-skill`(23,902)은 Cloudflare를 안 써도 쓸 수 있고, 같은 회사의 공식 번들(2,974)의 8배다. `microsoft/SkillOpt`(17,979)도 Azure와 무관하고, `microsoft/skills`(3,075)의 5.8배다.

**빅테크가 제품 축을 벗어나면 개인 저장소와 같은 구간으로 올라온다.**

## 이유 2 — 설명이 선명하지 않다

스타가 붙으려면 저장소를 열어 보기 전에 무엇인지 알아야 한다.

| 저장소 | 설명 | 열어 봐야 아는가 |
|---|---|---|
| `ponytail` | 에이전트를 방 안에서 가장 게으른 시니어 개발자처럼 생각하게 만든다 | 아니오 |
| `humanizer` | 글에서 AI가 쓴 흔적을 제거한다 | 아니오 |
| `i-have-adhd` | 코딩 에이전트가 답을 묻어 버리지 않게 한다 | 아니오 |
| `superpowers` | 작동하는 에이전틱 스킬 프레임워크 및 소프트웨어 개발 방법론 | 아니오 |
| `google/skills` | Google 제품과 기술을 위한 에이전트 스킬 | **예** |
| `microsoft/skills` | SDK를 위한 스킬, MCP 서버, 커스텀 에이전트, Agents.md | **예** |
| `cloudflare/skills` | 에이전트에게 Cloudflare 위에서 빌드하는 법을 가르치는 스킬 | **예** |

아래쪽 셋은 **범주를 말하고 내용을 말하지 않는다.** "Google 제품을 위한 스킬"은 참이지만 155개 중 무엇이 있는지 알려 주지 않는다.

위쪽은 한 문장에 결핍과 해법이 다 있다. "답을 묻어 버리지 않게 한다"는 사용자가 겪은 일을 가리킨다.

### 공식 저장소가 그렇게 쓸 수 없는 이유

구조적이다. 공식 번들은 **범위가 열려 있다.** 스킬을 계속 추가하므로 설명이 특정 내용에 묶이면 안 된다. `google/skills`에 Ads 스킬이 추가됐을 때 설명이 "Cloud 작업을 돕는다"였다면 고쳐야 한다.

개인 저장소는 범위를 닫는다. `humanizer`는 영원히 글만 고친다. 그래서 설명을 뾰족하게 쓸 수 있다.

**범위를 닫는 것이 비용이고, 선명함이 그 대가다.**

## 이유 3 — 다중 하네스를 적극 지원한다

| 저장소 | 지원 하네스 | 주체 |
|---|---|---|
| `obra/superpowers` | 16개 | 개인 |
| `DietrichGebert/ponytail` | 20개 (배지 기준) | 개인 |
| `epoko77-ai/im-not-ai` | 4개 | 개인 |
| `openai/skills` | Codex | 빅테크 |
| `google/skills` | `.agents/`, `.claude-plugin/` | 빅테크 |
| `cloudflare/skills` | — | 빅테크 |

**개인 저장소가 경쟁사 도구를 더 적극적으로 지원한다.**

OpenAI가 자기 카탈로그를 Claude Code용으로 포장할 이유가 없다. 개인에게는 그 제약이 없고, 지원 범위를 넓히는 것이 순수한 이득이다.

이게 스타수에 직접 영향을 준다. 설치할 수 있는 사용자가 많으면 스타를 누를 사람도 많다. [4.1](../part4/01-taxonomy.md)에서 도구별 분류가 무의미해진다고 한 것의 이면이다 — 도구 중립성이 **경쟁 우위**가 됐다.

## 이유 4 — 검증이 어려운 유형이 상위에 몰린다

상위 5개 중 3개가 방법론형이다([5.4](../part5/04-patterns.md)).

| 유형 | 평가 | 상위권 비중 |
|---|---|---|
| 방법론형 | 주관적, 어렵다 | 높다 |
| 실행형 | 객관적, 쉽다 | 중간 |
| 지식형 | 사실 정확성 | 낮다 |

빅테크 공식 번들은 대부분 지식형이다. Google Cloud 사용법, Azure 비용 분석, .NET 개발 지식이다.

**지식형은 틀렸을 때 바로 드러난다.** API가 바뀌면 그 스킬은 틀린 답을 낸다. 그리고 수명이 가장 짧아서 계속 갱신해야 한다([4.2](../part4/02-three-types.md)).

방법론형은 틀렸는지 알기 어렵다. "이 방법론이 효과적이다"를 반박하려면 기준선 비교가 필요하고, 그건 대부분의 저장소에 없다.

**확인이 어려우면 반박도 어렵고, 반박이 없으면 주목이 유지된다.** 비판으로만 읽을 필요는 없다 — 방법론은 본래 측정하기 어렵다. 다만 29만 스타가 효과의 증거는 아니다.

**선점 효과가 크다.** 스타는 누적되고 사라지지 않는다([6.3](../part6/03-openai.md)에서 폐기된 저장소가 후속 저장소의 3.8배인 사례). 먼저 나온 저장소가 "이 영역의 그 저장소"가 되면 나중에 나온 것이 밀어내기 어렵다.

생태계 전체 생성 분포에서도 확인된다. 2025년 10월에 저장소가 3개에서 31개로 뛰었다([5.4](../part5/04-patterns.md)). 그 달에 들어온 쪽이 상위권을 잡았다.

## 이유 6 — 마케팅을 한다

개인 저장소에 있고 공식 저장소에 없는 것들이다.

`DietrichGebert/ponytail`의 README 상단이다.

```
로고 이미지 (다크 모드 대응)
부제: "그는 아무 말도 하지 않는다. 한 줄을 쓴다. 그게 작동한다."
Trendshift 배지
스타 배지 / 릴리스 배지 / npm 배지 / "works with 20 agents" 배지 / MIT 배지
```

`i-have-adhd`는 이름 자체가 마케팅이다. 기능이 아니라 사용자의 상태를 이름으로 썼다.

`ponytail`의 "가장 게으른 시니어 개발자"도 그렇다. **기술적 설명 대신 캐릭터를 만들었다.**

공식 저장소가 이렇게 쓰지 않는 이유는 분명하다. 브랜드 톤이 있고, 승인 절차가 있다. "당신의 에이전트를 가장 게으른 시니어 개발자처럼 생각하게 만든다"가 회사 공식 저장소에서 나오기 어렵다.

## 그래서 개인 저장소가 더 나은가

아니다. 이 장의 결론을 그렇게 읽으면 틀린다.

6부에서 확인한 것을 다시 본다.

| 저장소 | 스타 | 평가 인프라 |
|---|---|---|
| `dotnet/skills` | 5,543 | 기준선 비교 + 평가 품질 게이트 + 통계적 검정력 |
| `NVIDIA/SkillSpector` | 19,226 | 보안 스캔 71패턴 + 서명 파이프라인 + SARIF |
| `google/skills` | 20,875 | `description` 설계 생태계 최고 수준 |
| `obra/superpowers` | 294,779 | 통합 테스트, 기준선 비교 없음 |

**엔지니어링 수준은 반대 방향이다.**

`dotnet/skills`는 스타 1.9%인데 평가 인프라가 생태계 최고다. `NVIDIA/SkillSpector`는 스킬 26.1%에 취약점이 있다는 통계를 제공하고 서명 파이프라인을 돌린다([6.8](../part6/08-others.md)). `google/skills`의 `index.json`은 제외 조건과 형제 스킬 교차 참조를 체계적으로 담았다([6.4](../part6/04-google.md)).

개인 저장소에도 예외가 있다. `DietrichGebert/ponytail`의 세 팔 벤치마크와 `addyosmani/agent-skills`의 3단 평가 체계는 생태계 상위다([7.2](02-addyosmani.md), [7.3](03-single-purpose.md)).

**정리하면 이렇다.**

| | 개인 저장소 | 빅테크 공식 저장소 |
|---|---|---|
| 강한 것 | 범위 선명도, 도구 중립성, 속도, 전파력 | 평가 인프라, 보안 검증, 지식 정확성, 갱신 지속성 |
| 약한 것 | 평가, 검증이 들쭉날쭉 | 범위가 제품에 묶임, 설명이 뭉뚱그려짐 |
| 스타수 | 높다 | 낮다 |

**스타수는 왼쪽 열을 재고 오른쪽 열을 재지 않는다.**

## 실무 판단

| 필요 | 어디를 보나 |
|---|---|
| 지금 당장 쓸 범용 스킬 | 개인 저장소 상위권 |
| 특정 플랫폼 작업 | 해당 빅테크 공식 저장소 |
| 평가 설계를 배운다 | `dotnet/skills`, `addyosmani/agent-skills` |
| `description` 설계를 배운다 | `google/skills`의 `index.json` |
| 설치할 스킬의 안전성 검사 | `NVIDIA/SkillSpector` |
| 갱신이 중요한 지식 | 빅테크 공식 (갱신 주기가 짧다) |

마지막 줄이 중요하다. 지식형 스킬은 수명이 짧고 갱신이 생명이다. `google/skills`가 수집 시점 이틀 전에 푸시됐고, 개인 큐레이션 목록 여럿이 5개월째 멈췄다([7.4](04-awesome-lists.md)). **유지 지속성에서는 조직이 이긴다.**
